# 🟥 ARCUS test tool

Мини-инструмент для тестирования платёжного терминала через библиотеку
**ARCUS 2 / 2.1** (Ingenico / Inpas, «Arcom Universal EMV POS»).

Веб-интерфейс с тремя действиями: **Purchase** (оплата), **Admin Menu**
(меню администратора) и универсальный **СТОП** (отмена текущей операции).
Под капотом — прямые вызовы нативной `arccom.dll` через FFI (koffi).

> 📘 Подробное руководство по интеграции с ARCUS (API, примеры, диаграммы) —
> в отдельном файле **[INTEGRATION.md](INTEGRATION.md)**.

---

## ✨ Возможности

- **Purchase** — оплата по карте: `ITPosSet(amount/currency)` → `ITPosRun` → чтение результата.
- **Admin Menu** — вызов меню администратора терминала (`cmd=99`).
- **СТОП** — отмена текущей операции (`Stop`). Работает для платёжных операций
  (Purchase и т.п.); меню администратора отменяется только на самом терминале
  (ограничение библиотеки — см. [Ограничения](#-известные-ограничения)).
- Веб-UI, доступный по сети — управлять можно с другого компьютера (например, с Mac).
- Портативная сборка под Windows **без установки Node.js**.

---

## 🏗️ Архитектура

`arccom.dll` — нативная Windows-библиотека, работающая с физически подключённым
терминалом. Поэтому процесс тула выполняется **на Windows** (рядом с DLL), а
интерфейс открывается по сети с любого устройства.

```mermaid
flowchart LR
    Dev["Браузер<br/>(Mac / любой ПК)"] -->|"HTTP :3000"| Node["arcus-test-tool<br/>(Node + koffi)"]
    Node -->|"FFI"| Dll["arccom.dll"]
    Dll <-->|"USB / RS232"| Term["Терминал"]
    Term <-->|"TCP/IP"| Bank["Банк"]

    style Node fill:#1a7f37,color:#fff
    style Dll fill:#c8102e,color:#fff
    style Term fill:#444,color:#fff
    style Bank fill:#0b5fff,color:#fff
```

**Ключевая деталь:** `ITPosRun` — блокирующий вызов. Чтобы кнопка СТОП работала
во время операции, `ITPosRun` запускается асинхронно (koffi `.async`, отдельный
поток), а `Stop(obj)` вызывается из основного потока по тому же указателю.

## 📋 Требования

| Требование | Детали |
|------------|--------|
| **ОС рантайма** | Windows (там, где установлена `arccom.dll` и подключён терминал) |
| **Разрядность** | ⚠️ рантайм Node должен совпадать с разрядностью DLL. У типовой ARCUS DLL — **32 бита (x86)** → нужен 32-битный Node |
| **DLL** | `arccom.dll` + её зависимые DLL (обычно `C:\Arcus2\DLL\`) |
| **Для разработки** | Node.js 18+ (на Mac/Linux — для правок и сборки портатива) |

## 🚀 Быстрый старт

### Вариант A — разработка (с установленным Node)

```bash
npm install
npm start          # http://localhost:3000
```

Путь к библиотеке и коды команд задаются переменными окружения (см.
[Конфигурация](#️-конфигурация)):

```bash
ARCUS_LIB="C:\\Arcus2\\DLL\\arccom.dll" npm start     # Windows
```

### Вариант B — портативная сборка для Windows (без Node на целевой машине)

```bash
./build-portable.sh           # соберёт portable/ и dist/...zip
```

Скопируйте `dist/arcus-test-tool-portable-x86.zip` на Windows, распакуйте и
запустите `run.bat`. Интерфейс откроется на `http://<IP-этого-ПК>:3000`.

## 🧠 Обзор кода (`index.js`)

Файл намеренно одностраничный (для простоты переноса) и поделён на блоки:

### 1. Конфигурация
Путь к DLL и коды команд из переменных окружения.

### 2. Загрузка библиотеки и FFI-биндинги
Через `koffi.load()` + `lib.func()` объявляются прототипы (все `__cdecl`):

| JS-обёртка | Сигнатура C | Назначение |
|------------|-------------|------------|
| `CreateITPos` | `void* CreateITPos()` | создать объект-сессию |
| `DeleteITPos` | `void DeleteITPos(void*)` | удалить объект |
| `ITPosSet` | `int ITPosSet(void*, char* key, char* val, int size)` | задать вход |
| `ITPosGet` | `int ITPosGet(void*, char* key, char* buf, int size)` | прочитать выход |
| `ITPosRun` | `int ITPosRun(void*, int cmd)` | выполнить операцию |
| `Stop` | `void Stop(void*)` | отменить текущую операцию |

### 3. Чтение результата
`readField()` / `collectResult()` вытаскивают выходные ключи (`response_code`,
`rrn`, `auth_code`, `pan`, `text_message`, …) в объект.

### 4. Логика операций
- `startOperation({ cmd, label, params })` — универсальный запуск: `Create` →
  `Set(params)` → **`ITPosRun.async`** (фоновый поток) → по завершении `Get` +
  `Delete`. Состояние «занято» хранится в `state`.
- `stopCurrent()` — вызывает `Stop` по активному объекту (`mode: "current"`),
  либо, если активной операции нет, по временному объекту (`mode: "forced"`).

### 5. HTTP-сервер + встроенный HTML
Маленький сервер на `node:http` + одностраничный UI (HTML/JS встроены строкой),
который опрашивает `/status` и рисует кнопки/результат.

## ⚙️ Конфигурация

Все настройки — через переменные окружения (см. `run.bat`):

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `ARCUS_LIB` | `Arccom.dll` (Win) / `./libarccom.so` | путь к библиотеке |
| `ARCUS_CMD_PURCHASE` | `1` | код команды Purchase (из `ops.ini`) |
| `ARCUS_CMD_ADMIN` | `99` | код команды «меню администратора» |
| `PORT` | `3000` | порт веб-интерфейса |

## 🌐 HTTP API

| Метод | Путь | Тело | Описание |
|-------|------|------|----------|
| `GET` | `/` | — | веб-интерфейс |
| `GET` | `/status` | — | `{ running, startedAt, lastResult }` |
| `POST` | `/purchase` | `{ amount, currency }` | запустить оплату |
| `POST` | `/admin` | — | открыть меню администратора |
| `POST` | `/stop` | — | отменить текущую операцию |

Пример:

```bash
curl -X POST localhost:3000/purchase -H 'Content-Type: application/json' \
     -d '{"amount":"2000","currency":"860"}'

curl -X POST localhost:3000/stop
```

Результат операции (`lastResult`) содержит `op`, `runResult`, `fields` (выходные
ключи), `error`, `finishedAt`.

## 📦 Сборка портативной версии

`build-portable.sh` делает всё автоматически:

1. ставит зависимости (если нужно);
2. скачивает официальный **32-битный** `node.exe` (по умолчанию `v22.22.3`);
3. собирает `portable/` (node.exe + `index.js` + `node_modules/koffi` только под
   `win32_ia32` + `run.bat`);
4. пакует `dist/arcus-test-tool-portable-x86.zip`.

```bash
./build-portable.sh              # версия Node по умолчанию
./build-portable.sh v22.22.3     # явная версия (нужна win-x86 сборка)
```

> ℹ️ Single-exe (`pkg`) под win-x86 не собирается: yao-pkg не публикует 32-битную
> базу Node. Поэтому используется портативный `node.exe` рядом со скриптом —
> установка Node на целевой машине всё равно **не требуется**.

## 🖥️ Развёртывание на Windows

1. Скопируйте `dist/arcus-test-tool-portable-x86.zip` на машину с терминалом.
2. Распакуйте (например в `C:\arcus-tool\`).
3. При необходимости поправьте путь к DLL в `run.bat` (`ARCUS_DIR`).
4. Запустите `run.bat`.
5. Откройте `http://<IP-этого-ПК>:3000` с любого устройства в сети.

> Если интерфейс не открывается по сети — разрешите порт в брандмауэре:
> ```cmd
> netsh advfirewall firewall add rule name="ARCUS tool 3000" dir=in action=allow protocol=TCP localport=3000
> ```

## ⚠️ Известные ограничения

- **СТОП не закрывает «Меню администратора».** Меню — интерактивный режим на самом
  терминале; `Stop` его не прерывает (поведение `arccom.dll`/прошивки). Закрывается
  красной клавишей на устройстве. Для платёжных операций СТОП работает.
- **Разрядность.** 64-битный процесс не загрузит 32-битную DLL
  (`Cannot load 'Intel 386+' DLL in 'AMD x64' process`) — используйте x86-сборку.
- **Коды команд** (`cmd`) зависят от `ops.ini` конкретного терминала — сверяйтесь.
- **Кодировка.** Текстовые поля приходят в CP1251; в текущей версии тула читаются
  как есть (для тестов достаточно, для продакшена — декодировать CP1251→UTF-8).
- **Безопасность.** Сервер слушает сеть без авторизации — запускайте только в
  доверенной сети.
